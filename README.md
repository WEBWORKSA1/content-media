# Content.Media

**The Creator Economy Operating System** — free calculators, an auditable benchmark database, and a
curated directory of content and AI tools.

A fully static site. No server, no framework, no build toolchain beyond Python 3. Hosts on the
GitHub Pages free plan.

---

## Quick start

```bash
python3 build.py              # regenerate every page for GitHub Pages (Jekyll layout mode)
python3 build.py --static     # or: fully self-contained HTML for any host / local preview
python3 -m http.server 8000   # preview a --static build at http://localhost:8000
```

There are no dependencies. Python 3.8+ is the only requirement.

**How GitHub Pages builds it:** in the default mode each page is written as a small file with
front matter (title, description, canonical, schema) and its body, and every page shares one
shell at `_layouts/default.html` — header, footer, and the domain-enquiry bar. GitHub Pages runs
Jekyll automatically on push, so there is no workflow to maintain. You can also edit any page
directly on GitHub: open e.g. `guides/<slug>/index.html`, change the body, commit.

## What's in here

```
build.py                    generator — run this after any change
_src/
  config.py                 ← everything configurable lives here
  layout.py                 page shell, header, footer, ad units
  components.py             forms, cards, FAQ, CTAs, lead form
  guides.py                 the 12 editorial guides
  pages_*.py                page builders
  data/tools.py             the directory dataset
assets/
  css/site.css              design system (light + dark)
  js/site.js                runtime: forms, search, theme, nav
  js/benchmarks.js          every published benchmark constant
  js/calc.js                the calculator engine
  js/directory.js           directory faceting
  data/                     generated JSON + the benchmark CSV
<everything else>           generated HTML — do not edit by hand
```

Generated pages are committed so GitHub Pages can serve them directly. If you edit a page by
hand and later re-run `build.py`, the build overwrites it — so make lasting changes in `_src/`.

## Before going live — set these in `_src/config.py`

| Setting | What to put there |
|---|---|
| `ADS["publisher"]` / `ADS["slots"]` | Your AdSense publisher ID and slot IDs. Ad units render as HTML comments until this is set. |
| `ADS["ads_txt"]` | Same publisher ID, in `pub-XXXX` form (not `ca-pub-`) |
| `ANALYTICS["ga4_id"]` | Your GA4 measurement ID |
| `DONATE[...]` | Stripe Payment Link URLs, Buy Me a Coffee / Ko-fi handles |
| `FORM_ALIAS` | FormSubmit's `el/<alias>` once activated (see below) |
| `AUDIENCE` | Real reach figures. Leave `None` and the media kit says "on request" rather than inventing a number. |
| `SITE["youtube_channel"]`, `SITE["twitter"]` | Your real handles |

Then add real listings to `JOBS` and `VIDEOS` in `_src/pages_content.py` — both render honest empty
states until you do.

## The contact address

The site uses a single contact address, and **it appears nowhere in this repository** —
not in the HTML, not in the data files, not in this README. It is stored XOR-masked (key `0x5A`) and base64-encoded as a single token in
`_src/config.py`, and reassembled only in the browser at runtime by `assets/js/site.js`. Every
`mailto:` link and every form endpoint is built from that function.

Every build verifies this automatically: `build.py` decodes the token in memory and scans every
file in the repository for the address. If it finds it anywhere, the build fails.

**Activating forms:** every form posts JSON to `https://formsubmit.co/ajax/<address>`. FormSubmit
requires one submission to activate the address — submit the contact form once and confirm the
email. After that, set `FORM_ALIAS` in config to the `el/<alias>` string FormSubmit issues, which
removes the address from network requests entirely.

## Hosting on GitHub Pages

Settings → Pages → Source: **Deploy from a branch** → `main` / `(root)`.

`CNAME` and `_config.yml` are generated by the build (`--static` builds add `.nojekyll`). For the custom domain, point DNS at GitHub:

```
A     @   185.199.108.153
A     @   185.199.109.153
A     @   185.199.110.153
A     @   185.199.111.153
CNAME www webworksa1.github.io
```

Then tick **Enforce HTTPS** once the certificate provisions.

## Adding content

| To add | Edit |
|---|---|
| A calculator | A spec in `_src/pages_tools.py` + an engine in `assets/js/calc.js` |
| A guide | One dict in `_src/guides.py` |
| A directory tool | A row in `_src/data/tools.py` |
| A job or video | `JOBS` / `VIDEOS` in `_src/pages_content.py` |
| Nav, footer, pricing, ads | `_src/config.py` |

Run `python3 build.py`. The sitemap, search index, RSS feed and benchmark CSV regenerate
automatically.

## Editorial rules the code enforces

- Calculators always return a **range**, never a single number, and print their assumptions.
- Audience figures render as "on request" until real numbers are set — the code will not invent one.
- Ad slots collapse to comments rather than reserving empty boxes.
- The job board's published rule is that listings without a salary range are declined.
